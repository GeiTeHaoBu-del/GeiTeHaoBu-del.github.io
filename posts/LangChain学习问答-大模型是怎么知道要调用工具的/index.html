LangChain学习问答：大模型是怎么"知道"要调用工具的？

发表于 2026-06-15 更新于 2026-06-19 分类于 LangChain ， AI问答
深度追问大模型工具调用的底层机制——模型从哪知道该查哪个城市？不绑定工具时会怎样？长文本下模型如何"记住"自己有工具？答案指向自注意力机制。

前言

上一篇问答覆盖了 LangChain 框架的基础知识。这篇是追问篇——围绕”模型到底是怎么知道要调用工具的”这个问题，一层一层往底层挖，最终落到 Transformer 的自注意力机制上。

Q11：模型从哪知道要查哪个城市的天气？

代码里只是 bind_tools([get_weather]) 然后问”请问北京今天的天气如何”，模型怎么知道该查北京？

答案是模型从用户输入里自己提取的。 整个过程分三步：

  1. bind_tools([get_weather]) 把工具定义（名字、描述、参数 schema）塞进发给模型的请求体
  2. 模型同时看到两样东西：用户说”请问北京今天的天气如何” + 有个工具叫 get_weather，参数是 loc: str，描述写着”查询指定城市的即时天气，建议传英文城市名”
  3. 模型推理：用户问天气 + 有天气工具 → 应该调用 get_weather，参数 loc 填 Beijing（docstring 里写了建议英文，所以模型把”北京”翻译成 Beijing）

模型没有读你的函数代码，也没有直接调 HTTP 请求。它只看了三样东西——工具名、工具描述、参数 schema——然后从用户的话里自己推断出该填什么参数。

这也是为什么工具描述写得好不好，直接影响模型能不能正确调用。如果只写”查天气”三个字，模型可能不知道 loc 该传中文还是英文；而 docstring 写了”建议优先传英文城市名，如 Beijing、Shanghai”，模型才大概率把”北京”翻译成 Beijing。

Q12：没绑定任何工具时，模型会一直尝试寻找工具吗？

不会。模型根本不知道工具的存在，除非你主动告诉它。

模型不是在”尝试找工具”，而是被动地看请求里有没有工具定义。有就看，没有就正常说话。就像你进一家餐厅，菜单上写了什么菜你才能点什么，没有的菜你根本不会去想。

Q13：绑定了工具后，模型怎么知道什么时候该调用？又是怎么”记住”自己有工具的？

这个问题要拆成两半回答。

先说”什么时候该调用”： 模型同时看到用户消息 + 全部工具定义，然后做一次推理，输出两种可能——要么直接回文字，要么返回 tool_calls 说”我想调这个工具”。判断的依据就是相关性：用户问题跟工具描述关联度高就调，关联度低就跳过。

再说”怎么记住”：模型不是”记住”自己有工具，而是每次请求都重新看一遍工具定义。

每次用户发一句话，程序都会构造一个新的 HTTP 请求发给模型，每一次请求里 tools 字段的内容都会完整带上：

模型处理每一轮请求时，看到的都是完整的对话历史 + 完整的工具定义。它不需要”记住”上一轮有没有工具，因为这一轮的请求里工具定义又在眼前了。

打个比方：不是你”记得冰箱里有牛奶”，而是你每次走进厨房，冰箱上都贴着一张清单写着”冰箱里有牛奶”。你每做一道菜之前都会看一遍这张清单，然后判断这道菜要不要用牛奶。清单不是你脑里的记忆，是每次都摆在眼前的信息。

所以：没有数据库存储、没有缓存存储、没有模型内部的”记忆”。是你的程序在每次请求时，主动把工具定义塞进请求体里。 这也是为什么工具越多，每轮请求的 token 消耗越大——每个工具的 name、description、args_schema 都要全文塞进去，不管这轮用不用。

Q14：3万字长文本下，模型怎么还能”记住”自己有工具？是自注意力机制吗？

是的，就是自注意力机制。 但”记住”这个词不够准确，更精确的说法是——模型不需要记住，因为它一直在看着。

人阅读3万字文章时，读到第10个问题时，前面看过的内容已经变成”记忆”了，你需要靠脑子回忆。但模型的推理方式不是这样的——它不是”读完再回忆”，而是把所有 token 同时摆在面前，一次性计算它们之间的关系。

当模型在生成第10个问题的回答时，它的自注意力机制在做的事情是：计算当前位置的 token 和前面每一个 token 之间的关联度。

模型在生成位置 5031 的 token 时，自注意力会计算它和位置 1-5030 每一个 token 的关联权重。如果第10个问题提到了”天气”，而工具定义里写着”查询天气”，这两个位置之间就会产生很高的注意力权重——模型不是”想起来了”，而是它一直在看着工具定义，只是第9个问题和工具的关联度低，第10个问题和工具的关联度高。

这跟人类的区别：

人类 模型
方式 读完后靠记忆回忆 所有 token 同时在场，注意力权重决定关联
“记住” 需要存到脑子里 不需要存储，因为原文就在输入里
遗忘 会忘 不会忘，但注意力权重可能被稀释

所以这里有一个真正的工程问题：输入越长，注意力越可能被稀释。 3万字文章 + 10个问题 + 工具定义的场景下，模型有时候会”忽略”工具——不是它忘了，而是注意力权重被大量文章内容分散了，工具定义的权重相对变低了。这也是为什么工程上会控制输入长度、把工具定义放在靠后的位置、或者用 RAG 先做一轮筛选再喂给模型。
